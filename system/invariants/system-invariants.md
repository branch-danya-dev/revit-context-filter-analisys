# Системные инварианты

## SI-01 · Revit остаётся источником истины для состояния среды
ContextFilter не становится владельцем Revit-документа, элементов, видов или выделения.

## SI-02 · Смысл фильтра не зависит от способа реализации в Revit
`FilterDefinition` определяет смысл фильтра. Возможность создать `ParameterFilterElement` — отдельный вопрос совместимости.

## SI-03 · Идентичность параметра не равна отображаемой подписи
Фильтр должен опираться на стабильный `ParameterKey`, а не только на имя, показанное пользователю.

## SI-04 · Отсутствующий и пустой параметр — разные состояния
Они не должны автоматически трактоваться одинаково.

## SI-05 · Ещё не загруженный параметр не считается отсутствующим
Неполный `ElementSnapshot` не доказывает отсутствие параметра у элемента Revit.

## SI-06 · Результат фильтра и действие — разные понятия
Один найденный набор может использоваться для выделения, скрытия, изоляции или создания штатного фильтра без изменения смысла исходного фильтра.

## SI-07 · Способ вычисления должен сохранять семантику
Инвертированный индекс, последовательный и параллельный проход должны давать один логический результат при одинаковых входных данных.

## SI-08 · Производное состояние имеет границы актуальности
Кэш, дерево, индексы и `FilterResult` действительны только относительно контекста Revit, из которого они получены.

## SI-09 · Жизненный цикл документа инвалидирует связанную с ним работу
После закрытия или смены документа старые фоновые задачи и состояние интерфейса не должны продолжать считаться текущими.

## SI-10 · Неактивный плагин не создаёт тяжёлую фоновую нагрузку
При закрытой панели тяжёлые операции `Idling` для сбора, индексации и подсветки не выполняются.

## SI-11 · Взаимодействие плагина уважает штатное управление Revit
Дополнительные горячие клавиши и жесты не должны переопределять привычную семантику Revit. Реальный конфликт `Ctrl + Click` привёл к изменению сочетания, последующему ограничению конфликтующего жеста и политике включения горячих клавиш пользователем.

## SI-12 · Сохранённая конфигурация проверяется перед использованием
Некорректные настройки не должны напрямую становиться рабочей конфигурацией.

## SI-13 · Ошибка не должна выглядеть как корректное пустое состояние
Сбой сбора, загрузки пресета или выполнения действия должен отличаться от корректного результата «ничего не найдено / нечего применить».

## SI-14 · Запись в Revit соблюдает правила транзакций среды
Действия, для которых Revit требует транзакцию, должны выполняться в корректной транзакционной границе.

## SI-15 · Исходные BIM-элементы не являются результатом фильтра
Сценарий фильтрации не должен удалять, перемещать или произвольно изменять исходные элементы модели.
