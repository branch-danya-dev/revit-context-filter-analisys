# Модель проверки

## Источники проверки

Для ContextFilter доступны четыре типа подтверждений:

1. первоначальные ТЗ заказчика;
2. уточнения требований с заказчиком и BIM-координатором;
3. реализованная архитектура, описанная в `PROJECT_ANALYSIS.md`;
4. пользовательское тестирование, стабилизация, финальная приёмка директором и внедрение.

## Цепочка проверки

```text
Требование
→ ожидаемое поведение системы
→ канонический владелец
→ представление в реализации
→ наблюдаемый результат
```

## Пример: фильтрация по типу

```text
бизнес-требование
→ семантика параметров и фильтра Domain
→ вычисление Application
→ значения снимков, полученные из Revit
→ итоговые ElementId
```

## Пример: пресеты

```text
требование повторного использования
→ Domain PresetDefinition
→ сценарии Application
→ JSON-хранилище Infrastructure
→ восстановление в UI
→ повторное вычисление в текущем контексте Revit
```

## Пример: жизненный цикл

```text
наблюдаемое поведение при тестировании
→ системный инвариант
→ исправление Revit/Application
→ повторное пользовательское тестирование
```

## Ограничение публичной проверки

Публичный аналитический репозиторий не содержит исходный код рабочего плагина. Поэтому он показывает связь между переданными материалами и документированной реализацией, но не должен выдавать документационную проверку за независимый аудит исходного кода.
