# Система

Этот раздел показывает **ContextFilter как одну систему**, а не как набор отдельных проектов решения.

Он отвечает на вопросы:

- где проходит граница плагина относительно Autodesk Revit;
- какие крупные части системы существуют и за что отвечают;
- как данные и пользовательское намерение проходят через Domain, Application, Infrastructure, UI и Revit;
- какие сквозные инварианты должны сохраняться;
- какие части модели пришлось пересмотреть после пользовательского тестирования;
- как проверяется согласованность требований, модели и реализации.

## Карта раздела

- [`architecture/`](architecture/) — контекст, границы и модель компонентов;
- [`flows/`](flows/) — сквозные сценарии между слоями;
- [`data/`](data/) — владение и движение ключевых данных;
- [`invariants/`](invariants/) — правила, которые должны оставаться истинными во всей системе;
- [`evolution/`](evolution/) — изменения модели после реального пользовательского тестирования;
- [`review/`](review/) — проверка согласованности и соответствия реализации.

## Система в одном представлении

```text
ПОЛЬЗОВАТЕЛЬ
  ↓
UI
  ↓
APPLICATION
  ↓
DOMAIN

INFRASTRUCTURE
  ↗

REVIT
→ точка входа среды
→ исходные данные
→ штатные действия
```

Фактическое направление зависимостей реализации:

```text
Revit → UI, Infrastructure, Application, Domain
UI → Application, Domain
Infrastructure → Application, Domain
Application → Domain
Domain → ∅
```

Направление зависимостей не означает владение состоянием. Autodesk Revit остаётся источником истины для документа, элементов, видов, выделения и штатного состояния API.

## Главный системный поток

```text
Рабочий контекст Revit
→ сбор
→ нормализация / проекция
→ формирование условий фильтра
→ вычисление в памяти
→ найденный набор элементов
→ выполнение выбранного действия в Revit
```

Подробные локальные модели находятся у своих владельцев: [`../domain/`](../domain/), [`../application/`](../application/), [`../infrastructure/`](../infrastructure/), [`../ui/`](../ui/), [`../revit/`](../revit/).
