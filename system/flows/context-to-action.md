# Контекст → фильтр → действие

Это основной сквозной сценарий системы.

## 1. Запуск
Пользователь открывает ContextFilter из Revit. UI запрашивает актуальную информацию о рабочем контексте через Application и границу Revit.

## 2. Выбор области
Пользователь выбирает `ActiveView`, `EntireDocument` или `CurrentSelection`. Область задаёт множество кандидатов, но ещё не является фильтром.

## 3. Сбор

```text
Запрос Application
→ сборщик Revit
→ правила поддерживаемых элементов
→ идентификаторы / записи дерева
→ ElementSnapshot
```

Большие наборы могут собираться порционно через `Idling`, но это меняет только способ выполнения, а не смысл результата.

## 4. Представление контекста
Формируются дерево Категория → Семейство → Тип, индекс параметров, доступные значения и вычисляемые свойства. Это производные представления текущего контекста Revit.

## 5. Формирование фильтра
Пользовательский выбор преобразуется в `FilterDefinition`. Быстрый фильтр — способ собрать каноническое определение Domain, а не отдельный язык фильтрации.

## 6. Вычисление

```text
FilterDefinition
+
ElementSnapshot[]
→ FilterEvaluator
→ найденные ElementId
```

Вычисление выполняется в памяти и само по себе не требует транзакции Revit.

## 7. Действие
Application рассчитывает целевой набор, а Revit реализует штатное действие: изменение выделения, временной видимости или создание совместимого `ParameterFilterElement`.

> **`FilterResult` описывает найденный набор. Действие описывает, что пользователь хочет сделать с этим набором. Это разные системные понятия.**
