# Сообщения и защитные ограничения

UI — место, где системное ограничение должно становиться понятным пользователю.

## Недоступная область

`ScopeOptionViewModel` поддерживает `BlockedReason`.

```text
вариант сейчас недоступен
!= вариант отсутствует в системе
```

Например, отсутствие подходящего документа или выделения должно отображаться как конкретное ограничение текущего контекста, а не как молчаливое отсутствие результата.

## Предупреждение для большого контекста

`EntireDocument` может быть дорогим для больших моделей. Реализация содержит порог предупреждения. Сам порог — деталь конфигурации; ответственность UI — показать предупреждение до дорогостоящей операции, не меняя смысл области.

## Ошибка загрузки пресета

```text
загрузка пресета не удалась
→ явное предупреждение
→ текущее корректное состояние UI остаётся отличимым
```

## Ошибка действия

```text
FilterResult существует
→ запрошено действие
→ ошибка ниже по цепочке
→ видимое сообщение пользователю
```

Ошибка Revit-действия не должна интерпретироваться как `0` совпадений или успешное выполнение.

## Прогресс

Длительные операции могут показывать прогресс. Отображение прогресса не владеет механизмом порционного сбора или планированием `ExternalEvent`.

> UI должен делать ограничения системы видимыми, а не скрывать их за пустым состоянием, молчаливым обходом или изменением намерения пользователя.
