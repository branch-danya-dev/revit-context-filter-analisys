# Собранный контекст

`CollectedContext` — контракт Domain для собранного рабочего контекста.

Подтверждённая структура:

```text
CollectedContext
├─ Scope
├─ ElementIds
├─ CacheKey
├─ TreeRoots
└─ Records
```

`ContextCacheKey` содержит признаки документа, вида, области, выделения и версии изменений, необходимые для различения контекстов.

## Семантическая роль

```text
Какие элементы входят в область кандидатов?
→ ElementIds

Как они представлены для навигации?
→ TreeRoots / Records
```

Физическое хранение этих данных в одном DTO не делает производные проекции источником истины.

На идентичность контекста могут влиять документ, активный вид, `CollectionScope`, текущее выделение и версия изменений модели.

`CollectedContext` является производным состоянием. Сам факт существования объекта не доказывает его актуальность. Domain хранит идентичность и происхождение, а Application/Revit решают: переиспользовать, локально обновить, инвалидировать или собрать заново.

## Инварианты

1. `CollectedContext` не становится источником истины для Revit-документа.
2. Корректный пустой контекст отличается от отсутствующего или устаревшего.
3. Множество кандидатов соответствует заявленному `Scope`.
4. Изменение исходного контекста может сделать производный контекст устаревшим.
5. Навигационное дерево не добавляет элементы вне множества кандидатов.
