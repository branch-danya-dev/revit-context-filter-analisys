# ContextFilter — бизнес-правила

> Фиксирует устойчивые правила пользовательского поведения продукта, которые должны сохраняться независимо от конкретной реализации.

## BR-01 · Рабочий контекст определяет допустимую область поиска
Фильтр работает только внутри выбранного рабочего контекста. Элемент за его пределами не должен появляться в результате только потому, что удовлетворяет условию по параметру.

## BR-02 · Фильтр не расширяет предварительное выделение самопроизвольно
Если пользователь выбрал `CurrentSelection`, дальнейшая фильтрация работает только внутри исходного выделения.

## BR-03 · Конкретное условие должно давать конкретный результат
При фильтрации по определённому типу или значению элементы с другими значениями не должны попадать в найденный набор. Это правило напрямую связано с проблемой из первоначального ТЗ.

## BR-04 · Категория / Семейство / Тип — последовательное сужение
Выбор верхнего уровня навигации ограничивает последующие варианты и рабочий набор.

## BR-05 · AND и OR имеют различный смысл
```text
AND → элемент удовлетворяет всем активным условиям группы
OR  → элемент удовлетворяет хотя бы одному активному условию группы
```
Внутренняя модель логического дерева принадлежит Domain, но пользовательский смысл AND/OR является продуктовым правилом.

## BR-06 · Отсутствующий и пустой параметр не должны смешиваться
```text
Параметр отсутствует
!=
Параметр существует, но не имеет содержательного значения
```

## BR-07 · Результат фильтра и действие — разные шаги
Сначала система определяет найденный набор, затем пользователь выбирает действие. Один и тот же набор можно использовать для разных действий без изменения смысла фильтра.

## BR-08 · Exclude требует исходного выделения
Исключение имеет смысл только относительно существующего набора выбора и не является эквивалентом отрицательного фильтра.

## BR-09 · Временная видимость не меняет BIM-модель
Hide / Isolate / inverse isolation управляют представлением элементов и не должны удалять или произвольно изменять исходные элементы.

## BR-10 · Штатный фильтр Revit — дополнительное представление
Если текущий `FilterDefinition` совместим с возможностями Revit, пользователь может создать штатный фильтр. Если условия богаче возможностей Revit, сам фильтр ContextFilter остаётся корректным; недоступным становится только создание штатного фильтра.

## BR-11 · Полный пресет сохраняет конкретные условия
Полный пресет сохраняет структуру фильтра вместе с конкретными значениями для повторного применения.

## BR-12 · Шаблон сохраняет структуру без фиксированных значений
Шаблон предназначен для повторного использования логики фильтра в новом контексте, где актуальные значения выбираются заново.

## BR-13 · Ошибка загрузки не является корректным пустым состоянием
Если сохранённые данные не удалось прочитать, продукт должен отличать это от ситуации «у пользователя нет сохранённых пресетов».

## BR-14 · Смена документа завершает старый рабочий контекст
Интерфейс и фоновые операции не должны продолжать вести себя так, будто предыдущий Revit-документ всё ещё текущий.

## BR-15 · Плагин не должен перехватывать управление Revit без необходимости
Горячие клавиши и дополнительные жесты не должны разрушать штатные пользовательские сценарии Revit.

История изменения:

```text
Ctrl + Click
→ конфликт со штатным множественным выделением Revit
→ во время тестирования заменён на Ctrl + Shift + Click
→ в итоговом состоянии конфликтующий жест ограничен / отключён
→ горячие клавиши включаются только пользователем
```

Каноническое правило важнее конкретного сочетания клавиш: дополнительный способ запуска не должен переопределять штатную семантику ввода Revit.

## BR-16 · Основной сценарий должен работать без горячих клавиш
Пользователь должен иметь возможность открыть ContextFilter через Ribbon независимо от настроек быстрых клавиш.

## BR-17 · Неактивный плагин не должен вести активную пользовательскую сессию
Когда рабочая панель закрыта, система не должна продолжать тяжёлую фоновую работу, предназначенную только для активного взаимодействия с фильтром.
