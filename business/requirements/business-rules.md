# ContextFilter — бизнес-правила

> Фиксирует устойчивые правила пользовательского поведения продукта, которые должны сохраняться независимо от конкретной реализации.

## BR-01 · Контекст определяет допустимый universe

Фильтр работает только внутри выбранного рабочего контекста.

```text
Active View
или Entire Document
или Current Selection
        ↓
кандидаты для дальнейшей фильтрации
```

Элемент вне текущего context не должен появляться в результате только потому, что он удовлетворяет условию по параметру.

## BR-02 · Фильтр не расширяет предварительную выборку самопроизвольно

Если пользователь выбрал `Current Selection` как scope, дальнейшая фильтрация должна работать внутри этой исходной выборки.

## BR-03 · Конкретное условие должно давать конкретный результат

Если пользователь фильтрует по определённому типу или значению параметра, элементы с другими значениями не должны попадать в matched set.

Это правило напрямую связано с проблемой, описанной в первоначальном ТЗ.

## BR-04 · Category / Family / Type — последовательное сужение

Выбор верхнего уровня навигации ограничивает последующие варианты и рабочий набор.

Пользователь не должен видеть результат, который противоречит выбранной классификации.

## BR-05 · AND и OR имеют различный смысл

```text
AND
→ элемент удовлетворяет всем активным условиям группы

OR
→ элемент удовлетворяет хотя бы одному активному условию группы
```

Конкретная внутренняя модель логического дерева принадлежит Domain, но пользовательский смысл AND/OR является продуктовым правилом.

## BR-06 · Missing и empty не должны смешиваться

Если продукт позволяет фильтровать отсутствие параметра и пустое значение, эти состояния должны трактоваться как разные пользовательские условия.

```text
parameter absent
!=
parameter exists but has no meaningful value
```

## BR-07 · Filter result и действие — разные шаги

Сначала система определяет matched set, затем пользователь выбирает действие.

```text
Filter intent
→ matched elements
→ user action
```

Один и тот же найденный набор может использоваться для разных действий без изменения смысла фильтра.

## BR-08 · Exclude требует исходного selection context

Действие исключения имеет смысл только относительно существующего набора выбора.

Если исходного selection нет, продукт не должен изображать `Exclude` как эквивалент обычному отрицательному фильтру.

## BR-09 · Temporary visibility не меняет модель

Hide / Isolate / inverse isolation управляют представлением элементов на текущем виде и не должны удалять или изменять исходные BIM-элементы.

## BR-10 · Native Revit filter — дополнительное представление

Если текущий filter intent совместим с возможностями Revit, пользователь может создать штатный Revit filter.

Если filter intent богаче native возможностей, сам фильтр ContextFilter остаётся действительным; недоступным становится только конкретное действие создания native filter.

## BR-11 · Full preset сохраняет конкретный intent

Полный пресет сохраняет структуру фильтра вместе с выбранными значениями, необходимыми для повторного применения.

## BR-12 · Template preset сохраняет структуру без фиксированного значения

Template предназначен для повторного использования логики фильтра в другом текущем контексте, где пользователь выбирает актуальные значения заново.

## BR-13 · Ошибка загрузки не является корректным пустым состоянием

Если сохранённые данные не удалось прочитать, продукт должен отличать это от ситуации «у пользователя нет сохранённых пресетов».

## BR-14 · Смена документа завершает старый рабочий контекст

UI и фоновые операции не должны продолжать вести себя так, будто предыдущий Revit-документ всё ещё является текущим.

## BR-15 · Плагин не должен захватывать управление Revit без необходимости

Горячие клавиши и mouse gestures являются дополнительным способом взаимодействия и не должны разрушать базовые пользовательские сценарии Revit.

По результатам тестирования hotkeys стали opt-in, а конфликтующая комбинация `Ctrl + Click` была заменена.

## BR-16 · Основной сценарий должен оставаться доступным без hotkeys

Пользователь должен иметь возможность открыть и использовать ContextFilter через стандартную точку входа в Ribbon независимо от настроек быстрых клавиш.

## BR-17 · Неактивный плагин не должен вести активную пользовательскую сессию

Когда рабочая панель закрыта, система не должна продолжать тяжёлое поведение, предназначенное только для активной filter session.
