# ContextFilter — критерии приёмки

> Разделяет **формально переданные критерии**, **аналитически восстановленный базовый набор проверки** и **фактический результат проекта**.

## Что было в исходных ТЗ

Оба шаблона заказчика содержали раздел «Критерии приёмки», но конкретные ответы в нём не были заполнены.

Поэтому нельзя ретроспективно утверждать, что заказчик изначально передал формальный набор критериев приёмки с измеримыми порогами.

## Аналитически восстановленные критерии

Следующие критерии выводятся из явно подтверждённых функциональных требований и используются как проверяемая модель ожидаемого поведения. Это **не дословный текст исходного ТЗ**.

### AC-01 · Рабочий контекст отображается корректно
При запуске в поддерживаемой области пользователь получает элементы именно текущего рабочего контекста.

### AC-02 · Навигация соответствует модели
Представление Категория / Семейство / Тип не должно включать элементы, отсутствующие в текущем рабочем контексте.

### AC-03 · Фильтр по значению точен
Элемент попадает в найденный набор только если удовлетворяет заданному условию. Отдельная проверка нужна для фильтрации по типу, поскольку ошибочный выбор посторонних типов был отмечен заказчиком в первоначальном ТЗ.

### AC-04 · Предварительное выделение ограничивает поиск
При использовании текущего выделения как области поиска результат не выходит за пределы исходной выборки.

### AC-05 · Действие над выделением применяется к найденному набору
`Replace` / `Add` / `Exclude` изменяют пользовательское выделение в соответствии с выбранным действием, не меняя сами BIM-элементы.

### AC-06 · Hide / Isolate меняют только рабочее представление
Действия временной видимости применяются к ожидаемому набору и не удаляют и не модифицируют элементы модели.

### AC-07 · AND / OR дают различимый ожидаемый результат
Комбинация условий соответствует выбранной пользователем логике.

### AC-08 · Полный пресет можно повторно использовать
Сохранённый пресет восстанавливает соответствующие условия фильтра.

### AC-09 · Шаблон не требует старых фиксированных значений
Шаблон позволяет повторно использовать структуру фильтра и выбрать актуальные значения в текущем контексте.

### AC-10 · Ошибка не маскируется под успех
Если действие или восстановление данных не удалось, пользователь получает понятное уведомление, а система не отображает ошибку как корректный пустой результат.

### AC-11 · Смена или закрытие документа завершает старую сессию
Состояние и фоновые операции предыдущего документа не должны продолжать влиять на текущую работу.

### AC-12 · Неактивная панель не создаёт постоянную лишнюю нагрузку
Фоновое поведение, необходимое только активной работе с фильтром, прекращается после закрытия панели.

### AC-13 · Базовый сценарий Revit не зависит от горячих клавиш
Отключение горячих клавиш не лишает пользователя доступа к плагину; запуск из Ribbon остаётся рабочим.

## Фактическая проверка

После реализации проводилось пользовательское тестирование. По его результатам были устранены проблемы:

- некорректных сохранённых настроек;
- отсутствия уведомления при ошибке загрузки пресетов;
- продолжения фоновой работы после закрытия документа;
- сохранения состояния интерфейса при смене документа;
- постоянно активных горячих клавиш;
- автоматического открытия панели и лишней нагрузки при запуске Revit;
- конфликта `Ctrl + Click` с штатным множественным выделением Revit;
- постоянно активных обработчиков событий;
- ранней инициализации встроенных пресетов;
- выполнения изоляции вне требуемого транзакционного контекста;
- задержек при закрытии Revit.

После исправлений была передана новая сборка для повторного тестирования.

## Фактическая приёмка

```text
Разработка
→ пользовательское тестирование
→ стабилизация
→ повторная проверка
→ приёмка директором института
→ внедрение
→ использование
```

Плагин принят директором проектного института и внедрён. После внедрения заказчиком не сообщалось об ошибках или претензиях.

Не заявляются неподтверждённые показатели количества пользователей, подразделений или измеримого бизнес-KPI.
