# ContextFilter — критерии приёмки

> Разделяет **формально переданные критерии**, **аналитически восстановленный acceptance baseline** и **фактический outcome проекта**.

## Что было в исходных ТЗ

Оба customer templates содержали раздел «Критерии приёмки», но конкретные ответы в нём не были заполнены.

Поэтому нельзя ретроспективно утверждать, что заказчик изначально передал формальный набор acceptance criteria с измеримыми порогами.

## Аналитический acceptance baseline

Следующие критерии выводятся из явно подтверждённых функциональных требований и используются как проверяемая модель ожидаемого поведения. Это **не дословный текст исходного ТЗ**.

### AC-01 · Контекст отображается корректно

При запуске в поддерживаемом scope пользователь получает элементы именно текущего рабочего контекста.

### AC-02 · Навигация соответствует модели

Category / Family / Type представление не должно включать элементы, отсутствующие в текущем рабочем context.

### AC-03 · Фильтр по значению точен

Элемент попадает в matched set только если удовлетворяет заданному условию.

Отдельная проверка необходима для сценария фильтрации по типу, поскольку именно ошибочный over-selection был отмечен заказчиком в первоначальном ТЗ.

### AC-04 · Предварительный selection ограничивает поиск

При использовании текущего выбора как scope результат не выходит за пределы исходной выборки.

### AC-05 · Selection action применяется к matched set

Replace / Add / Exclude изменяют пользовательское выделение в соответствии с выбранным действием, не меняя сами BIM-элементы.

### AC-06 · Hide / Isolate меняют только рабочее представление

Temporary visibility actions применяются к ожидаемому набору элементов и не удаляют / не модифицируют элементы модели.

### AC-07 · AND / OR дают различимый ожидаемый результат

Комбинация условий соответствует выбранной пользователем логике.

### AC-08 · Preset может быть повторно использован

Сохранённый Full preset восстанавливает соответствующий filter intent.

### AC-09 · Template не требует старых фиксированных значений

Template preset позволяет повторно использовать структуру фильтра и выбрать актуальные значения в текущем контексте.

### AC-10 · Ошибка не маскируется под успех

Если действие или восстановление данных не удалось выполнить, пользователь получает понятное уведомление, а система не отображает failure как корректный пустой результат.

### AC-11 · Смена / закрытие документа не оставляет старую активную сессию

После закрытия или смены Revit-документа document-bound состояние и фоновые операции предыдущего context не должны продолжать влиять на текущую работу.

### AC-12 · Неактивная панель не создаёт постоянную лишнюю нагрузку

Фоновое поведение, необходимое только активной filter session, прекращается после закрытия панели.

### AC-13 · Базовый Revit workflow не блокируется плагином

Отключение hotkeys не лишает пользователя доступа к плагину; стандартный запуск из Ribbon остаётся рабочим.

## Фактическая валидация

После реализации проводилось пользовательское тестирование. По его результатам были обнаружены и устранены проблемы:

- некорректных persisted settings;
- отсутствия уведомления при ошибке загрузки presets;
- продолжения background work после закрытия документа;
- сохранения UI state при смене документа;
- постоянно активных hotkeys;
- auto-open панели и лишней нагрузки при запуске Revit;
- конфликта `Ctrl + Click` с native Revit multi-selection;
- постоянно активных event handlers;
- ранней инициализации built-in presets;
- выполнения isolation вне требуемого transaction context;
- задержек при закрытии Revit.

После исправлений была передана новая сборка для повторного тестирования.

## Фактическая приёмка

Подтверждённый outcome:

```text
implementation
→ user testing
→ stabilization fixes
→ final validation
→ acceptance by institute director
→ deployment
→ regular use
```

Плагин принят директором проектного института и внедрён. После внедрения заказчиком не сообщалось об ошибках или претензиях.

Не заявляются неподтверждённые показатели количества пользователей, подразделений или измеримого business KPI.
