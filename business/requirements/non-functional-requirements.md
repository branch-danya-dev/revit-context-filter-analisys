# ContextFilter — нефункциональные требования

> Фиксирует подтверждённые ограничения качества и требования устойчивости. Исходные требования и требования, выявленные пользовательским тестированием, разделены.

## Исходно подтверждённые ограничения

### NFR-01 · Целевая host-система

Плагин предназначен для Autodesk Revit.

### NFR-02 · Целевая версия

Расширенное ТЗ явно фиксирует **Revit 2025**.

### NFR-03 · Точность результата

Фильтрация должна возвращать только элементы, удовлетворяющие заданным пользователем условиям. Ошибочный over-selection недопустим как нормальное поведение.

### NFR-04 · Понятное сообщение об ошибке

Если действие не может быть выполнено, система должна сообщить пользователю краткую причину сбоя.

## Требования, выявленные в пользовательском тестировании

Следующие требования не были формально заполнены в исходном разделе «Производительность / Требования к качеству». Они были сформулированы по результатам эксплуатации тестовых сборок и исправлений перед финальным внедрением.

### NFR-05 · Безопасные пользовательские настройки

Некорректное persisted configuration не должно приводить к runtime failure.

Система должна валидировать и нормализовать настройки перед использованием.

### NFR-06 · Document-bound lifecycle

Операции, связанные с одним Revit-документом, не должны продолжать работу после закрытия этого документа или использовать его состояние после переключения контекста.

### NFR-07 · Сброс document-specific UI state

При смене документа состояние интерфейса, которое относится к предыдущему документу, должно быть сброшено или перестроено для нового контекста.

### NFR-08 · Фоновая активность только при использовании

Когда панель ContextFilter закрыта и пользователь не взаимодействует с плагином, тяжёлые фоновые операции и обработчики не должны продолжать создавать постоянную нагрузку на Revit.

### NFR-09 · No automatic heavy startup work

Плагин не должен автоматически открывать рабочую панель и выполнять необязательную тяжёлую инициализацию только из-за запуска Revit.

### NFR-10 · Lazy initialization where possible

Вспомогательные данные, не необходимые до первого использования функции, должны инициализироваться по требованию, если это уменьшает нагрузку при старте Revit.

### NFR-11 · Host interaction safety

Пользовательские shortcuts и mouse gestures не должны без необходимости конфликтовать с привычной семантикой Revit.

В частности, конфликтовавшая комбинация `Ctrl + Click` была заменена, а hotkeys сделаны opt-in.

### NFR-12 · Correct Revit API execution context

Операции, требующие Revit transaction / main-thread API context, должны выполняться только в разрешённом host-контексте.

### NFR-13 · Clean shutdown

При закрытии Revit плагин должен прекращать свою активность и освобождать ресурсы без заметных задержек, создаваемых оставшимися background handlers или незавершёнными задачами.

### NFR-14 · Preset load failure visibility

Сбой восстановления сохранённых пресетов не должен выглядеть как корректное пустое состояние. Пользователь должен быть предупреждён о проблеме загрузки.

## Что не подтверждено

В переданных ТЗ не заданы измеримые SLA для:

- максимального времени фильтрации;
- допустимого времени открытия панели;
- максимального размера модели;
- потребления RAM / CPU;
- количества одновременно обрабатываемых элементов.

В реализации существуют конкретные performance thresholds и оптимизации, но они относятся к техническому проектированию и не должны ретроспективно выдаваться за исходные customer NFR.
