# ContextFilter — продуктовые границы

> Канонически описывает, что входит в ContextFilter как продукт, что находится вне его ответственности и где проходит граница с Autodesk Revit.

## В границе продукта

### Рабочий контекст

Плагин поддерживает работу с элементами из выбранного пользовательского контекста:

- активный вид;
- весь документ;
- текущее / предварительное выделение.

Первоначальные ТЗ в первую очередь описывали активный вид, модель и предварительную выборку. Полный набор поддерживаемых scope фиксируется уже реализованной системой.

### Навигация по элементам

Пользователь может ориентироваться в элементах через представление:

```text
Category
→ Family
→ Type
```

Эта навигация помогает сузить рабочий набор перед параметрической фильтрацией.

### Параметрическая фильтрация

В продуктовую границу входят:

- выбор параметров;
- выбор или ввод значений;
- комбинация условий;
- AND / OR логика;
- различение отсутствующих и пустых значений там, где это поддерживается системой;
- работа как с Revit-параметрами, так и с системными признаками, доступными пользователю через фильтр.

### Действия над найденным набором

В границу входят пользовательские действия:

- выделить найденные элементы;
- добавить к выбору / заменить выбор там, где это поддерживает текущий режим;
- исключить найденные элементы из существующей выборки;
- временно скрыть;
- временно изолировать;
- выполнить инверсионную изоляцию;
- сбросить временное состояние видимости;
- создать совместимый штатный Revit filter, когда текущее filter intent может быть корректно представлено средствами Revit.

### Повторное использование filter intent

В продукт входят:

- сохранённые пресеты с конкретными значениями;
- шаблоны фильтра без фиксированных значений;
- повторное применение сохранённой структуры в новом рабочем контексте.

### Пользовательское взаимодействие

В продуктовую границу входит пользовательская панель / диалог ContextFilter и связанные с ним способы запуска, настройки взаимодействия и уведомления об ошибках.

## Вне продуктовой границы

ContextFilter не владеет BIM-моделью и не является системой редактирования модели.

Вне scope:

- произвольное изменение геометрии элементов;
- удаление элементов как результат фильтрации;
- массовое редактирование значений параметров как основная функция;
- изменение семейств или типоразмеров;
- управление жизненным циклом BIM-проекта;
- хранение мастер-копии данных Revit;
- отдельная задача по корректировке DWG, присутствовавшая среди переданных материалов, но не подтверждённая как часть ContextFilter.

## Граница с Revit

Autodesk Revit остаётся внешней host-системой и источником истины для:

- открытого документа;
- элементов;
- категорий, семейств и типов;
- параметров;
- активного вида;
- текущего selection;
- native visibility state;
- транзакций и ограничений Revit API.

ContextFilter читает эти данные, строит собственные производные представления для поиска и возвращает результат обратно в Revit через разрешённые действия.

```text
REVIT
  ↓ source BIM state
ContextFilter
  ↓ derived filter result
REVIT ACTION
```

## Ограничение по версии

Исходное расширенное ТЗ явно фиксирует целевую версию **Revit 2025**.

Поддержка других версий не считается подтверждённым бизнес-требованием этого кейса.

## Критерий изменения scope

Новая функция входит в ContextFilter только если она поддерживает основной цикл:

```text
определить рабочий контекст
→ найти нужные элементы
→ выполнить действие над найденным набором
```

Если новая функция начинает самостоятельно изменять содержимое BIM-модели или решает отдельную предметную задачу, её нельзя автоматически считать частью ContextFilter только потому, что она реализуется как Revit-плагин.
