# ContextFilter — основной пользовательский сценарий

> Описывает пользовательский путь от текущей BIM-задачи до действия над найденным набором элементов. Это business/user view; техническая реализация use cases описывается в `application/`.

## Основной сценарий

```text
Работаю в Revit
        ↓
Определяю область поиска
        ↓
Открываю ContextFilter
        ↓
Выбираю Category / Family / Type
        ↓
Выбираю параметр
        ↓
Выбираю / ввожу значение
        ↓
Комбинирую условия
        ↓
Получаю matched set
        ↓
Применяю действие
        ↓
Продолжаю работу в Revit
```

## Шаг 1 · Определить область поиска

Пользователь начинает не с абстрактного фильтра, а с текущей задачи в Revit.

В зависимости от задачи он может:

- работать с активным видом;
- использовать весь документ;
- предварительно выделить элементы и фильтровать только внутри selection.

Предварительное выделение полезно, когда пользователь уже пространственно ограничил интересующую часть модели и хочет уточнить набор по параметрам.

## Шаг 2 · Открыть ContextFilter

Основной безопасный сценарий запуска — команда из Ribbon.

Быстрые shortcuts являются дополнительной возможностью. После пользовательского тестирования они были сделаны opt-in, чтобы плагин не перехватывал привычные действия Revit без явного согласия пользователя.

## Шаг 3 · Выбрать классификацию элементов

Пользователь сужает рабочий набор через понятную структуру:

```text
Category
→ Family
→ Type
```

Например, вместо ручного поиска стены в модели пользователь может перейти к категории стен и нужному типу непосредственно в фильтре.

## Шаг 4 · Выбрать параметр

После определения интересующей группы пользователь выбирает признак, по которому нужно выполнить более точный поиск.

ТЗ приводит примеры таких параметров, как:

- Марка;
- Длина;
- Комментарии;
- Имя типа;
- Категория;
- Семейство и типоразмер;
- ряд ADSK-параметров для конструкций и арматуры.

Список в продукте не ограничивается этим перечнем как жёстким whitelist: перечисление в ТЗ отражало типичные рабочие потребности заказчика.

## Шаг 5 · Выбрать значение и логику

Пользователь выбирает существующее значение параметра или использует предусмотренный UI-ввод.

При нескольких условиях задаётся логика их связи:

```text
AND
→ нужны все условия

OR
→ достаточно одного из условий
```

## Шаг 6 · Получить текущий результат

Система показывает / использует matched set, соответствующий текущему filter intent.

При включённом динамическом выделении результат может визуально отражаться в модели во время настройки фильтра.

Важно:

> изменение фильтра изменяет найденный набор, но ещё не означает изменение BIM-элементов.

## Шаг 7 · Выполнить действие

Над найденным набором пользователь выбирает нужный outcome.

### Selection

- заменить выбор;
- добавить к выбору;
- исключить найденные элементы из существующей выборки.

### Visibility

- временно скрыть найденные элементы;
- изолировать найденные элементы;
- выполнить инверсионную изоляцию;
- вернуть temporary visibility state, если это предусмотрено текущим режимом.

### Native filter

Если текущий filter intent совместим с возможностями Revit, он может быть реализован как штатный Revit filter.

## Шаг 8 · Сохранить повторяемый сценарий

Если фильтр используется регулярно, пользователь может сохранить его как preset.

```text
Full preset
→ сохранить конкретные значения

Template preset
→ сохранить структуру
→ выбрать значения заново в новом контексте
```

## Альтернативный сценарий · Работа от selection

```text
Выбрать элементы в Revit
        ↓
Открыть ContextFilter
        ↓
Current Selection становится scope
        ↓
Уточнить набор параметрами
        ↓
Exclude / Select / Visibility action
```

Здесь особенно важно, что фильтр не должен самопроизвольно расширить universe за пределы исходного selection.

## Failure path

Если действие невозможно выполнить:

```text
user intent
→ attempt
→ failure
→ краткое понятное уведомление
→ модель не должна оказаться в неопределённом состоянии
```

Сбой загрузки пользовательских presets также должен быть видимым и не маскироваться под ситуацию «сохранённых пресетов нет».

## Завершение пользовательской сессии

После закрытия панели тяжёлое background behavior, относящееся только к активной filter session, не должно продолжать работать.

После закрытия / смены Revit-документа состояние предыдущего документа не должно сохраняться как текущий рабочий context.
