# ContextFilter — основной пользовательский сценарий

> Описывает пользовательский путь от текущей BIM-задачи до действия над найденным набором элементов. Это пользовательское представление; техническая реализация сценариев использования описывается в `application/`.

## Основной сценарий

```text
Работаю в Revit
        ↓
Определяю область поиска
        ↓
Открываю ContextFilter
        ↓
Выбираю Категорию / Семейство / Тип
        ↓
Выбираю параметр
        ↓
Выбираю или ввожу значение
        ↓
Комбинирую условия
        ↓
Получаю найденный набор
        ↓
Применяю действие
        ↓
Продолжаю работу в Revit
```

## Шаг 1 · Определить область поиска

Пользователь начинает не с абстрактного фильтра, а с текущей задачи в Revit.

В зависимости от задачи он может:

- работать с активным видом;
- использовать весь документ;
- предварительно выделить элементы и фильтровать только внутри этого выделения.

Предварительное выделение полезно, когда пользователь уже пространственно ограничил интересующую часть модели и хочет уточнить набор по параметрам.

## Шаг 2 · Открыть ContextFilter

Основной безопасный сценарий запуска — команда из Ribbon.

Горячие клавиши являются дополнительной возможностью и включаются пользователем. После тестирования конфликтующие сочетания были ограничены, чтобы плагин не перехватывал привычные действия Revit без явного согласия пользователя.

## Шаг 3 · Выбрать классификацию элементов

Пользователь сужает рабочий набор через понятную структуру:

```text
Категория
→ Семейство
→ Тип
```

Например, вместо ручного поиска стены в модели пользователь может перейти к категории стен и нужному типу непосредственно в фильтре.

## Шаг 4 · Выбрать параметр

После определения интересующей группы пользователь выбирает признак, по которому нужно выполнить более точный поиск.

ТЗ приводит примеры таких параметров, как:

- Марка;
- Длина;
- Комментарии;
- Имя типа;
- Категория;
- Семейство и типоразмер;
- ряд ADSK-параметров для конструкций и арматуры.

Перечень в ТЗ отражает типичные рабочие потребности и не трактуется как доказанный полный список всех поддерживаемых параметров.

## Шаг 5 · Выбрать значение и логику

Пользователь выбирает существующее значение параметра или использует предусмотренный интерфейсом ввод.

При нескольких условиях задаётся логика их связи:

```text
AND
→ нужны все условия

OR
→ достаточно одного из условий
```

## Шаг 6 · Получить текущий результат

Система показывает найденный набор, соответствующий текущим условиям фильтра.

При включённом динамическом выделении результат может визуально отражаться в модели во время настройки фильтра.

Важно:

> изменение фильтра изменяет найденный набор, но ещё не означает изменение BIM-элементов.

## Шаг 7 · Выполнить действие

Над найденным набором пользователь выбирает нужный результат действия.

### Выделение

- заменить текущее выделение;
- добавить к выделению;
- исключить найденные элементы из существующего выделения.

### Видимость

- временно скрыть найденные элементы;
- временно изолировать найденные элементы;
- выполнить инверсионную изоляцию;
- сбросить временное состояние видимости, если это предусмотрено текущим режимом.

### Штатный фильтр Revit

Если текущие условия фильтра совместимы с возможностями Revit, они могут быть реализованы как штатный фильтр Revit.

## Шаг 8 · Сохранить повторяемый сценарий

Если фильтр используется регулярно, пользователь может сохранить его как пресет.

```text
Полный пресет
→ сохранить конкретные значения

Шаблон
→ сохранить структуру
→ выбрать значения заново в новом контексте
```

## Альтернативный сценарий · Работа от выделения

```text
Выбрать элементы в Revit
        ↓
Открыть ContextFilter
        ↓
CurrentSelection становится областью поиска
        ↓
Уточнить набор параметрами
        ↓
Исключить / выделить / изменить временную видимость
```

Здесь особенно важно, что фильтр не должен самопроизвольно расширять область поиска за пределы исходного выделения.

## Сценарий ошибки

Если действие невозможно выполнить:

```text
Намерение пользователя
→ попытка выполнения
→ ошибка
→ краткое понятное уведомление
→ модель не должна оказаться в неопределённом состоянии
```

Сбой загрузки пользовательских пресетов также должен быть видимым и не маскироваться под ситуацию «сохранённых пресетов нет».

## Завершение пользовательской сессии

После закрытия панели тяжёлые фоновые операции, нужные только активной работе с фильтром, не должны продолжаться.

После закрытия или смены Revit-документа состояние предыдущего документа не должно сохраняться как текущий рабочий контекст.
