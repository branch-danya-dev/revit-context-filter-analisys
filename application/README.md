# Application

Слой Application отвечает за выполнение пользовательских сценариев поверх модели Domain.

Он не определяет смысл фильтра и не работает с Revit API напрямую. Его ответственность — связать шаги сценария, выбрать необходимые вычисления, вызвать порты и вернуть результат вызывающему слою.

```text
UI / внешний инициатор
        ↓
сценарий использования Application
        ↓
модель Domain + сервисы Application
        ↓
порт
        ↓
адаптер Revit / Infrastructure / UI
```

## Application владеет

- сценариями использования;
- координацией сценариев;
- построением производных представлений контекста;
- вычислением `FilterResult`;
- стратегиями вычисления;
- расчётом целевых наборов для выделения и видимости;
- анализом совместимости фильтра ContextFilter со штатным фильтром Revit;
- портами к внешним реализациям;
- рабочим кэшем и правилами зависимостей его уровней.

## Application не владеет

- семантикой `FilterDefinition`, `ParameterKey`, `PresetDefinition` — это [`domain/`](../domain/);
- состоянием WPF и представлением — это [`ui/`](../ui/);
- JSON-хранением — это [`infrastructure/`](../infrastructure/);
- `ExternalEvent`, транзакциями и Revit API — это [`revit/`](../revit/).

## Структура

- [`use-cases/`](use-cases/) — входные сценарии Application;
- [`context/`](context/) — подготовка контекста, дерево, индексы, значения и кэш;
- [`filtering/`](filtering/) — вычисление и анализ совместимости;
- [`actions/`](actions/) — расчёт и координация действий над найденным набором;
- [`ports/`](ports/) — границы с внешними адаптерами;
- [`diagrams/application-flow.puml`](diagrams/application-flow.puml) — общая цепочка.

```text
Смысл Domain != выполнение Application
Сценарий использования != команда UI
Порт Application != реализация адаптера
FilterResult != действие в Revit
Попадание в кэш != подтверждение актуальности источника
Способ вычисления != семантика фильтра
```
